# AGENTS.md

Guidance for AI agents working on this repository. The game design is in `docs/Tram-GDD.md`; controls and layout are in `README.md`; what is left to do is in `TODO.md` – start there, and tick items off as they are done.

## Project overview

Tram is an arcade tram-driving game played from the motorman's cab: drive along the rails, stop precisely on the marker at each platform, run the doors, depart. Low-poly 3D, a mobile-first browser game (portrait first, landscape supported). The target host is GitHub Pages. Current state: **M1 vertical slice plus the first part of M2** (GDD §15) – Altstadt Line 1, Hafenberg Line 4, Neustadt Line 9 and a training line; lever, physics with grades and adhesion (wet rails), precision stops, doors, speed limits and curves, ride comfort, passengers with destinations whose mood is the score, timetable, tram signals, traffic hazards, a lifting bridge, a tunnel, points (junctions), a single-track section with a tram the other way, the bell, request stops, stars and saved progress, HUD and sound.

## Technical rules

- **Vanilla JS + ES modules, no bundler and no npm.** Three.js `0.160.0` is loaded from jsDelivr via the `importmap` in `index.html`. Don't add a build step or `package.json` unless explicitly asked.
- **The font is DINish** (a DIN 1451 look, like German street and transit signs), self-hosted in `fonts/dinish/` (weights 400/600/700/800, SIL OFL – keep `OFL.txt` with it); no font CDN. The HUD canvas uses the same font (`FONT` in `js/ui/hud.js`) and squeezes long texts with `maxWidth`.
- **`index.html` must stay in the repo root.** Everything else goes into subfolders. All paths are relative (GitHub Pages serves from a subdirectory).
- **No PWA** (manifest, service worker) until the user asks for it. Until then the game also stays a normal browser page: no fullscreen request.
- Everything is **in English**: UI text, code comments, docs.
- Code style: 2 spaces, semicolons, single quotes, brief comments only where something isn't obvious. Scratch objects used in hot loops live at module level (no per-frame allocation).
- Gameplay tuning (physics, brakes, stop rating, city) belongs in `js/config.js`, not in scattered numbers. Values must stay consistent with the GDD (§5 table: P4 0→50 km/h ~15 s, B4 stop from 50 km/h ~60 m, EB ~35 m).
- Lines are listed in `data/routes/index.json` (`{ id, file, city, name, from, to, stops }`), easiest first. Every line is open from the start: the stars are a rating per line, not a key. The menu reads only this index; a line's route file is loaded when it is chosen, and the previous world is disposed (`disposeWorld` in `js/main.js`; materials shared between worlds carry `userData.shared`).
- Routes are data: `data/routes/*.json` – `id`, `name`, `city`, `look` (a key of `LOOKS` in `js/config.js`: street width, paving, houses, sky, fog, sea colour), optional star thresholds `stars: [1★, 2★, 3★]` as satisfaction 0–1 (default `PASSENGERS.stars`), track pieces (`straight`, `curve` with radius / angle / dir, optional `grade` in % and `limit` in km/h), stops by distance `s` (optional fixed `dep` "06:15:30", `request: true`), line `speed`, slow zones `limits: [{ from, to, kmh }]`, `startTime`, an optional timetable `slack`, `intersections: [{ s, signal }]` (on straights, clear of platforms) and `hazards: [{ type: leftTurn | jaywalker | parked | cyclist | forklift, s, chance, … }]` (`leftTurn` takes the oncoming `lane` offset), `double: true` (a double-track line: the other track drawn left of ours), `single: [{ from, to }]` (single-track sections, with a tram the other way), `junctions: [{ s, way, branch, pieces }]` (points: the line goes `way`, the branch – drawn, not driven – goes `branch` along its own `pieces`), `roundabout: { s, radius }` (on a flyover), `squares: [{ from, to, side }]` (no houses on that side), `quays: [{ from, to, side, edge }]` and `views: [{ from, to, side }]` (a terrace with a balustrade), `sea` (the sea level: the ground plane becomes the sea), `wet: [{ from, to }]` (wet rails), `bridge: { s, length, chance }` (a lifting bridge on a straight, its stop line `STREET.stopLineBack` before it), `tunnels: [{ from, to }]` and `landmarks: [{ type: cathedral | gate | market | cranes | ship | lighthouse, … }]` (`js/world/landmarks.js`). Keep a line around 3–6 minutes (with the bridge wait).

## Conventions

- Units: meters, seconds, radians. Y is up.
- **The track is the backbone.** Everything is positioned by `s` (distance along the route) and a lateral offset. `Track.at(s, off)` returns position, heading, curvature and grade. Heading 0 = forward along −Z, positive curvature turns right, positive offset = right of the track. An object facing along the track has `rotation.y = −heading`.
- `tram.s` is the position of the **tram front**. The stop marker `stop.s` is where the front should stop; doors are listed as distances behind the front.
- Notches: `EB = -5`, `B4..B1 = -4..-1`, `N = 0`, `P1..P4 = 1..4`.
- Gameplay logic doesn't import Three.js, so it can be tested in Node (`node` with `import()` of the module files): `js/core/tram.js`, `run.js`, `crowd.js`, `comfort.js`, `timetable.js`, `street.js`, `js/world/track.js`, `limits.js`. Test tuning changes with scripted drivers (bots) and measurements.
- **Speed limits** (`js/world/limits.js`): the posted limit per meter (`raw`) is what the signs say; the tram obeys the lowest limit under its whole body (`at(s)`), so a higher limit applies once the rear has passed the sign. Curves are signed for `√(LIMITS.aLat · R)` rounded down to 5 km/h. There is no derailment: too fast, the tram shakes (`run.rough`) and the comfort falls – strongly in a curve (lateral acceleration), less on a straight (`COMFORT.overspeed`). Overspeed has no HUD text: the speed turns amber/red, and the comfort bar, the shaking and the sound tell it. Text prompts are kept for what the player can't see and must act on (doors interlock, wheels sliding or slipping, points set wrong).
- **Timetable** (`js/core/timetable.js`): generated from a reference driving profile (full power to just under the limit, braking at `TIMETABLE.refBrake`, expected dwell) times the slack, departures rounded up. All times are game seconds since midnight; the game clock runs `TIMETABLE.timeScale` × real time. A departure is the first movement after a served stop.
- **The street** (`js/core/street.js`, rendered by `js/entities/traffic.js`): agents live in track coordinates (`s`, `off`, `dir`). A collision is an agent's footprint inside the tram's swept path (`STREET.envelope`) overlapping the tram body. Hazards commit only while the tram can still stop calmly (`commit*`) and never once it couldn't stop at B4 (`fair*`); downhill (`street.loss`) and on wet rails (`street.cap` = `STREET.wetBrake`) both distances grow. Keep that rule for every new hazard and check it with a careful bot over many seeds (no collisions allowed). Tram signals are a green wave for the timetable (`tRef`, shifted by `street.lag`). Hazard randomness comes from the run seed (`run.reset(seed)`).
- **The lifting bridge** (`Bridge` in `js/core/street.js`, drawn by `js/world/structures.js`) is listed with the tram signals (HUD, signal head). When it is due to lift, the warning ("prepare") starts where a calm stop is still possible plus a random extra, so racing it is sometimes possible and sometimes means passing a stop signal. It never lifts with the tram past its stop line; driving onto it while it is up ends the run. The delay a lift causes is excused: `run.shift` moves the whole timetable (`run.sched`, `run.depAt`) and the green wave.
- **Points** (`Junction` in `js/core/street.js`): ◄ ▲ ► buttons (A/D, ←/→) appear within `JUNCTION.show`; points not set for the line trip the emergency brake where it still stops the tram before them (`tram.trip`) – the tram never takes a branch. Branch tracks start at the junction's pose (`new Track(pieces, step, start)`); the city clears buildings off their streets.
- **Single-track sections** (`SingleTrack` in `js/core/street.js`, a signal like the bridge): the other track (`otherTrack` in `js/world/track.js`) merges into ours. The tram the other way (an agent of kind `tram`) reaches its stop line around a punctual tram's arrival (`SINGLE.early … late`), so there is usually a short wait; whoever is in first holds the section, and a tram driven in on the stop aspect meets it head on (it stops on sight and backs out, unless they collide). The timetable allows `TIMETABLE.singleAllowance` per section.
- **Adhesion** (GDD §5): on wet rails (`run.grip(s)` → `tram.step(dt, grade, grip)`) a service brake or power above `PHYSICS.wetGrip` slides or slips the wheels (`tram.slide`, `tram.slip`; HUD prompt, cab lamp, sound); the emergency brake still works. Standing with any brake notch or open doors holds the tram on any grade.
- On a phone in portrait, people are a few pixels tall at the distance that matters, so the HUD marks hazards worth watching (`TrafficView.markers`) and warns about anything on the tracks ahead.
- Grades: the physics uses the average grade under the tram body (`track.slope(s - length, s)`) and the camera a smoothed slope, so piece joints never cause jerk. The ground plane (`groundLevel` in `js/world/frame.js`) is the sea, or the lowest point of the line; buildings, cross streets and landmarks reach down to it (`block`). On the inside of tight curves the city leaves out buildings that would reach across the curve centre.
- Tunnels and the bridge are left out of the street (`deck` gaps in `js/world/city.js`) and built in `js/world/structures.js`. Tunnel interiors use an unlit material; inside, `main.js` darkens the fog and the cab (`structures.darkness`), and tunnels hide hazard markers (`structures.hides`).
- **Progress** (`js/core/progress.js`): best score, stars and the perfect-run badge per line in `localStorage` (wrapped in try/catch; the key is versioned – bump it when the score changes meaning). An accident ends the run; there is no continuing.
- **Passengers and the score** (`js/core/crowd.js`, GDD §6.3): every passenger waits at one stop and rides to another with an anger 0–1 (a lasting part, and a "shaken" part from a rough ride that fades on a smooth one). Anger comes from low comfort, lateness at their stop, the stop error, missed stops, being left behind, emergency stops (in proportion to the speed), signals, doors away from a platform and bumps – each recorded by cause (`crowd.lost`) for the results. Score = Σ (1 − anger) × `PASSENGERS.points`, shown only at the end; stars by the average satisfaction. Comfort (`js/core/comfort.js`) is the instantaneous ride quality: jerk (`tram.da`), lateral acceleration, overspeed, the emergency brake. All tuning is in `PASSENGERS` and `COMFORT`; check it with bots (a careful driver near 100%, sloppy stops, a speeder and leaving early clearly worse).
- The cab is a separate scene rendered after `renderer.clearDepth()`; the driver's eye is at (0,0,0) in cab space. The cab follows the body heading; the view turns slightly into curves (`VIEW.lookAhead`).
- Static city geometry is merged per chunk (`CITY.chunk` m of track), one draw call each, hidden beyond `CITY.drawAhead`.
- Simulation runs at a fixed 60 Hz step; rendering interpolates `s` between steps.

## Mobile view and controls

- `resize()` in `js/main.js` handles both orientations: the optical centre is moved up with `camera.setViewOffset` (35% from the top in portrait), so the street is above and the cab with the thumbs is below.
- The master controller (`js/core/input.js`) uses relative drag with notches and haptic ticks; EB sits below an extra gap (a detent). `input.layout()` must run while the lever is visible (it measures the element).
- Doors are interlocked (GDD §4.1): they open only at standstill and traction is cut while they are open.

## Testing

- Start a server with `python -m http.server 8765`. **Don't use port 8080** (another app's service worker on the user's machine).
- The browser caches modules served by `http.server`: hard-reload (Ctrl+Shift+R) after changes, or use a server that sends `Cache-Control: no-store`.
- `?debug` shows a state readout and exposes `window.tram = { game, tram, run, track, input, sound, camera }`. Measure with console scripts (stopping distances, ratings) instead of judging by eye.
- To check the phone layout, inject a 390×780 (portrait) and an 844×390 (landscape) `<iframe>` into a page from the same server – a page that doesn't run the game itself.
- Test on a real phone early (GDD §15).
- The console must stay clean.
